# Substrate Self-Location

## Declared level

S3

The human directs and verifies; the AI develops. Preparation fixes the
contract and the derivation rationale, but provider selection, process
boundaries, and profile contents are resolved at build time against 2026
capability evidence — a true S4/S5 posture would resolve those live from the
spec alone, which this project does not claim.

## Pre-locked decisions

- The twelve SPEC clauses and their EVAL bindings (spec.md v1.1.0, carried
  through plan v1.2.1). A builder may not renegotiate them; disagreement
  enters as a layer-scoped change request against intent.md.
- Phase order A1 → A2 → A3 → A4 → B (plan §7). Desktop phases gate Android;
  Android may not be silently dropped.
- MIT root license and no-AGPL rule (constitution G4, plan CTX-006).
- VoiceInk independence and macOS-evidence quarantine (constitution P3).
- Eval separation: private cases live at
  `~/.strata/evals/voice-unification/evals.md` and are unseen by the builder.

## Live-resolved decisions

- Which candidate fills each registry slot (research-2026-10.md §§1–5 are
  candidates with swap criteria, never mandates). Selection happens at build
  time with recorded probe evidence, not from inherited pins.
- Process/thread boundaries for capture, playback, dialogue, and dictation
  (plan §2 leaves this to implementation).
- Saved profile contents and hardware floors (v2/profiles.yaml pattern).
- Exact configuration schema, secret-store backend per OS, and diagnostic
  formats — constrained by intent/spec, shaped by the target platform.

## Empirical memory state

Partial. This preparation creates the first ledger
(`ledger/ledger.md`, SEQ 1–8) from inspected live-tree evidence
(registry.ts provider set, v2/profiles.yaml, slots/ ABCs, d81069e research

## Known reach

- What is claimed without runtime proof: every acceptance outcome in
  spec.md (no target-specific evidence is attached by this preparation;
  constitution G2 stays open until the test matrix runs).
- Windows-native dictation and Android delivery are the two highest-risk
  reaches; plan CTX-005 requires capability checks before delivery promises.
- Holding twelve blind evals outside the tree is preparation, not isolation:
  genuine held-out evaluation additionally needs an evaluator context whose
  files the builder cannot read; that isolation is NOT established here.
